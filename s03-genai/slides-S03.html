Hace bien

No garantiza

Tokens

Un token no es una palabra

El modelo no lee "Bebidas": lee fragmentos. La pregunta “¿Cuál es el margen de la categoría Bebidas?” son unos 13-14 tokens aproximados — signos, mayúsculas y palabras poco frecuentes cuentan aparte.

Por qué importa: cada token cuenta contra el presupuesto de la ventana de contexto y contra el costo del endpoint. Un prompt "prolijo" en español puede costar más tokens que uno en inglés.

Calculadora oficial de tokens: platform.openai.com/tokenizer ↗

Ventana de contexto

El modelo solo ve lo que cabe en la conversación

Instrucciones, pregunta, evidencias, herramientas y respuesta compiten por el mismo presupuesto.

Más contexto no siempre es mejor: el contexto irrelevante es ruido caro.

Misma pregunta, distinta temperatura

Qué cambia y cuándo conviene cada una

Temperatura“¿Cuál es el margen de Bebidas?” (sin evidencia)Conviene cuando…
0 – 0.2Inventa un número — casi siempre el mismo en corridas repetidasNecesitás una respuesta reproducible: SQL generado, clasificación, extracción estructurada
0.5 – 0.7Inventa un número — distinto en cada corridaRedacción, resumen, variaciones de copy donde la diversidad suma
1.0+Inventa varios números, a veces con formato inconsistenteLluvia de ideas, generación creativa; casi nunca para respuestas que citan un dato

Ninguna temperatura evita que invente: solo cambia cuán distinto es el invento entre corridas. Reproducible no es lo mismo que correcto.

Recuerdas esos tres números

−41.714,07 · −20.826,47 · +267.868,18

En la S01, el mismo Genie crudo respondió tres veces distinto a "¿cuál es el margen de Bebidas?". No fue la temperatura la culpable: fue preguntarle algo que el dato no contiene.

Bajar la temperatura a 0 no arregla esto — solo hace que el modelo invente el mismo número, con la misma confianza, todas las veces. Eso lo resolvemos en el Bloque 3 con grounding, no con menos temperatura.

Técnicas de grounding

Grounding no es una sola técnica

Retrieval-augmented

Recupera chunks relevantes desde tablas, documentos o Vector Search y los inyecta como contexto.

Tool grounding

El modelo llama una función autorizada que calcula el dato; la aplicación devuelve el resultado.

SQL grounding

La consulta determinista agrega primero; el modelo solo explica hechos ya calculados.

Vocabulario técnico

Contexto, evidencia y fuente no son sinónimos

Contexto

Todo lo que recibe el modelo: instrucciones, pregunta, historial y evidencia.

Evidencia

Fragmento o resultado recuperado que puede respaldar una afirmación concreta.

Grounding es el mecanismo de conectar la generación con evidencia externa verificable. No garantiza verdad: hay que medir relevancia, cobertura y fidelidad.

Grounding: controles

Una respuesta grounded necesita cuatro controles

1

Recuperación: seleccionar evidencia relevante, no “pasar toda la base”.

2

Identidad: conservar documento, chunk, versión y timestamp para citar.

3

Restricción: indicar “si no está en la evidencia, dilo”.

4

Verificación: evaluar retrieval y respuesta por separado.

Qué hace mejor a una variante

No es la que siempre da un número

Una variante es mejor si cita fuente cuando la evidencia existe, y se abstiene explícitamente cuando no. Inventar un número con confianza es siempre la peor respuesta posible, aunque "suene" más útil.

Cápsula · selección de modelo

La tarea decide la familia

El modelo más grande no siempre es la mejor elección: importa la calidad necesaria, la latencia, el costo y el nivel de control.

TareaFamilia recomendadaPor qué
Chatbot de soporteLLM generalista pequeño/medianoBuen diálogo, instrucciones y herramientas; escalar solo si la evaluación lo exige.
Extracción y clasificaciónMini/SLM con salida estructuradaMenor costo y latencia; temperatura baja y esquema validable.
Razonamiento, código o planificaciónModelo de razonamientoMás cómputo interno para problemas de varios pasos; suele costar más y responder más lento.
AgenteModelo con tool calling + sistema de herramientasEl agente no es solo el modelo: requiere política, memoria, permisos, observabilidad y evaluación.

Cápsula · taxonomía

No todo lo que llamamos “modelo” es lo mismo

Modalidades

Multimodal: combina texto, imagen, audio o video. STT/ASR: voz → texto. TTS: texto → voz. STS: voz → voz para conversación en tiempo real.

Especialización

Embeddings: texto → vectores para búsqueda. Reranker: reordena candidatos recuperados. Visión/documentos: interpreta imágenes, tablas, formularios y layout.

Eficiencia

Mini/SLM: tareas acotadas, routing y baja latencia. Cuantizado: 8/4 bits para ejecutar con menos memoria; puede reducir costo con alguna pérdida de calidad.

Arquitectura y sistema

MoE es una arquitectura de expertos, no una tarea. Un sistema agentic añade herramientas, memoria, reglas y un bucle de acción al modelo.

Regla práctica: primero define la tarea y sus pruebas; después elige modalidad, capacidad, tamaño y despliegue.
